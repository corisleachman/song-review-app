02

The visual standard

One shell, one set of parts. Every Song Room email is built from these.

A Header: SONG ROOM logo · workspace namealways
B Eyebrow: what happened (NEW VERSION, NEW COMMENT…)always
C Headline: who did what, in one sentencealways
D Song card: artwork, title, version, statussong emails
E Content block: notes, comment text, or explanationif present
F One primary button + one text linkalways
G Footer: why you got this, settings, song-room.livealways
  1. Dark canvas, 600px wide. Charcoal #0E0A0A body, #1C1515 cards, hard 1px #2E2626 rules, zero radius. Same as the app, so the email feels like a window into it.
  2. Red is for the action, straw is for the highlight. The one primary button in each email is brand red (#C0392B) with off-white text. Straw marks the eyebrow and the version tag. Nothing else competes for attention.
  3. Type. The song title is set in Thunder where the mail app loads web fonts (Apple Mail, iOS) and falls back to a heavy condensed system face elsewhere (Gmail, Outlook). Everything else is DM Sans → Helvetica → Arial. The logo is an image, so it's always on-brand.
  4. Say what it is in the subject and the first line. Song name first in the subject so a busy inbox sorts itself by song.
  5. Every email ships with a plain-text twin and a hidden preheader line (the grey preview text in the inbox).
  6. One button, phone-sized. 48px tall, full width on phones, label says the destination (“Listen to Version 5”, not “Open”). No secondary link unless it goes to a real page.
  7. Footer explains the email. Which workspace, why you got it, and a link to notification settings.

Artwork needs one decision before we build. Song artwork sits in private storage and the app's signed image links expire after 10 minutes, but people open emails hours later. The cleanest fix is a small email-only image route that serves a 240px thumbnail behind a long-lived signed link (for example 30 days), falling back to the initials tile once it expires. That touches the same artwork-privacy code Codex is hardening, so it should go in after Codex is done.

  
Two behaviour fixes to bundle in: stop sending the version email to the person who uploaded it (comment emails already skip the author), and respect the workspace “owner only” notification setting the way comment emails do.
